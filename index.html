1. Installation Commands

If you don't have Podman and Flyctl installed, run the following commands to install and initialize the environment on macOS:

# 1. Install Podman and Flyctl via Homebrew brew install podman flyctl # 2. Initialize a Podman machine (allocate CPUs and memory) podman machine init --cpus 2 --memory 4096 --rootful=false # 3. Start the Podman machine podman machine start

2. Step-by-Step: Pulling Images & Debugging

Follow these steps to pull a remote Fly.io image and debug it locally using Podman:

Step A: Authenticate with Fly.io

fly auth login

Step B: Pull Remote Images

Find your image URL from Fly.io and pull it using Podman (we use the AMD64 architecture flag to match Fly.io environments):

# Show the currently deployed image on Fly.io fly image show # Pull the image locally podman pull --arch amd64 registry.fly.io/your-app-name:deployment-01

Step C: Run and Debug

Run the container locally and expose its ports. Use interactive mode to get inside the shell:

# Run the app in detached mode, exposing port 8080 podman run -d -p 8080:8080 --name local-debug-app registry.fly.io/your-app-name:deployment-01 # View realtime logs to spot startup errors podman logs -f local-debug-app # Execute into the container to inspect the filesystem podman exec -it local-debug-app /bin/sh

3. Common Use Cases

Use Case 1: Testing Multi-Arch Builds on Apple Silicon

Developers on M1/M2/M3 Macs need to ensure their containers run properly on Fly.io's Intel/AMD servers. By using Podman's QEMU integration, developers can test the exact linux/amd64 environment locally without pushing broken builds to production.

Use Case 2: Inspecting Environment Variables & Secrets

When an app crashes on Fly.io due to missing environment variables, developers can run the image locally with Podman, passing in mock secrets (e.g. podman run -e DATABASE_URL=mock...) to replicate the failure and verify the fix before deploying.

Use Case 3: Offline Development

Instead of relying on remote builders, a developer on a plane or without internet access can build the OCI container image locally via podman build, test it extensively, and defer the fly deploy --local-only execution until connectivity is restored.
